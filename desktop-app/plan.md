# ***Monomer***

Установка [Monomer](https://github.com/fjvallarino/monomer?tab=readme-ov-file#readme)

```bash
git clone https://github.com/fjvallarino/monomer-starter.git <your-app-name>

# установить дополнительные пакеты в зависимости от ОС

cd your-app-name
stack build
# или
cabal build
```

Приложение c Monomer имеет пять основных компонентов, которые предоставляются функции startApp:

- Модель: содержит данные, специфичные для вашего приложения.
- События: генерируются действиями пользователя или асинхронными задачами.
- Функция создания пользовательского интерфейса: создает пользовательский интерфейс, используя текущую модель.
- Обработчик событий: реагирует на события и может обновлять модель, запускать асинхронные задачи и другие действия.
- Конфигурация: несколько вариантов указания размера окна, доступных шрифтов и темы.

## Модель

```haskell
newtype AppModel = AppModel {
  _clickCount :: Int
} deriving (Eq, Show)

```
Модель представляет состояние приложения. Здесь можно хранить все, что моделирует интересующий нас предмет. При запуске приложения нам необходимо предоставить исходную модель.

## События

```haskell
data AppEvent
  = AppInit
  | AppIncrease
  deriving (Eq, Show)
```

Тип событий представляет различные действия, на которые может реагировать наш обработчик событий. Это алгебраический тип данных, значения которого могут принимать аргументы в зависимости от события. Событие щелчка не нуждается в аргументах, но события onChange требуют получения аргумента, соответствующего типу содержимого, обрабатываемого виджетом.

 ## Построение интерфейса

 Функция build UI заботится о создании дерева виджетов. Всякий раз, когда модель изменяется, эта функция вызывается и создается новая версия дерева виджетов. Эта новая версия дерева виджетов будет объединена с предыдущей версией.

```haskell
buildUI
  :: WidgetEnv AppModel AppEvent
  -> AppModel
  -> WidgetNode AppModel AppEvent
buildUI wenv model = widgetTree
```

Как WidgetEnv (информация о среде, которую можно использовать при создании пользовательского интерфейса), так и WidgetNode (результат создания пользовательского интерфейса) получают тип модели и тип событий в качестве параметров типа.
Далее объявляются параметры, которые получает функция:

- wenv: сокращение от Widget Environment, включает в себя информацию об ОС, размере окна, статусе ввода, фокусе и некоторых других элементах.
- модель: текущее, определенное пользователем состояние приложения.

Наконец, возвращается WidgetNode, который может быть отдельным виджетом или более сложным макетом.

## обработка событий

```haskell
handleEvent
  :: WidgetEnv AppModel AppEvent
  -> WidgetNode AppModel AppEvent
  -> AppModel
  -> AppEvent
  -> [AppEventResponse AppModel AppEvent]
handleEvent wenv node model evt = case evt of
  AppInit -> []
  AppIncrease -> [Model (model & clickCount +~ 1)]
```

Опять же, у нас есть WidgetEnv и WidgetNode, но теперь у нас также есть AppEventResponse, который принимает те же два типа параметров (типы модели и события).

Параметры:
 - wenv: среда виджетов.
 - узел: текущий узел. Обычно мы не будем использовать этот параметр, но он позволяет проверить базовую древовидную структуру.
 - модель: текущее состояние.
 - evt: событие, которое нужно обработать.

Обычный процесс состоит в сопоставлении ожидаемых событий (определенных в типе событий) и возврате списка ответов для обработки средой выполнения.

## Конфигурация

```haskell
config = [

  appFontDef "Regular" "./assets/fonts/Roboto-Regular.ttf",

```
По умолчанию в стартовом приложении задано несколько параметров конфигурации, включая заголовок окна, тему, один шрифт и событие, которое будет генерироваться при запуске.

## Линзы

Линзы в Haskell это набор типов и функций, которые могут быть удобным средством получения и установки полей, а также средством обхода различных структур данных.

Monomer использует линзы в своем коде, а также предусмотрен специальный модуль (Monomer.Lens) для использования линз в программном интерфейсе. Код приложения также использует линзы: это автогенерируемые линзы для модели и некоторых других структур.

Среди операторов чаще всего используются следующие три:
- ^. (view): получение значения поля структуры данных, на которое указывает линза.
- .~ (set) : присваивание значения полю структуры данных, на которое указывает линза.
- &        : этот оператор делает возможным множественные присваивания в одном выражении. 

Для присваивания полям типа Maybe a используется оператор ?~. Это пример использования призм (Prizm), так как данные типа Maybe a могут быть представлены как призма (и в данном случае при автогенерации линз это так и делается).
